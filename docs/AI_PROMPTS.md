# Лог AI-промптів

Цей файл фіксує запити, які використовувалися під час AI-assisted розробки. Після кожної ітерації результат перевірявся через diff, тести/статичний огляд і коригувався окремими комітами.

## 1. Базовий каркас

**Запит:**

> Створи в поточному репозиторії мінімальний Laravel 11 + Vue 3 + Vite проєкт для демо платформи бонусів. Додай SQLite-конфігурацію, Sanctum як токен-автентифікацію, базову модель User з грошовим балансом, API/web маршрути, Blade entrypoint і npm/composer конфігурацію. Підготуй README із локальним запуском. Не додавай бізнес-логіку промокодів на цьому етапі.

**Ітерація:**

Каркас адаптовано під Laravel 11 bootstrap API (`bootstrap/app.php`) і SQLite, щоб наступні зміни можна було комітити поверх чистої основи.

**Коміт:** `Initialize Laravel and Vue application`

## 2. Тікет 1 — API

**Запит:**

> Реалізуй Тікет 1 для Laravel API: POST /api/promo/claim і GET /api/promo/history. Код промокоду обов’язковий, 6–12 латинських літер/цифр; гравець тільки з auth:sanctum. Перевіряй існування, активність, expiry і повторне використання. Успіх має атомарно збільшувати баланс, а not found/expired/already used — повертати різні зрозумілі помилки. Записуй відхилені спроби в історію.

**Уточнення після першої реалізації:**

> Не використовуй float для грошей. Зберігай баланс і суму бонусу в integer minor units. Додай транзакцію, lockForUpdate на user і promo code, щоб паралельні запити не зробили подвійне нарахування або lost update. Поверни в API форматовані десяткові рядки.

**Ітерація:**

Додано `balance_minor`/`amount_minor`, `PromoClaim`, стабільні коди помилок, пагінацію й фільтр `status`. Додані feature-тести для формату, not found, expired, duplicate та ізоляції історії.

**Коміти:** `Implement promo claim and history`, `Limit promo API to claim and history`

## 3. Тікет 1 — Vue

**Запит:**

> Додай Vue 3 інтерфейс, який звертається до API через axios: login із demo credentials, збереження Bearer token, відображення балансу, форма claim з loading/success/error, список історії з датою/сумою/статусом, фільтр status і пагінація. Причину backend-помилки покажи користувачу.

**Ітерація:**

Форма коду отримала нативні min/max/pattern обмеження, помилки validation/domain зведені в одне повідомлення, а після claim історія перезавантажується.

## 4. Тікет 2 — revoke

**Запит:**

> Додай PATCH /api/promo/{claimId}/revoke. Операція має бути доступна лише власнику claim зі статусом applied, в одній транзакції списувати суму й оновлювати статус на revoked. Повторний виклик має повернути 409 без повторного списання; не дозволяй від’ємний баланс. Додай Vue-кнопку «Скасувати» з confirm, оновленням балансу/історії та тести.

**Ітерація:**

Додано окрему перевірку власника через `forUser`, блокування user і claim, помилку `insufficient_balance`, а також регресійні тести для чужого claim, повторного revoke й недостатнього балансу.

**Коміт:** `Add safe promo revocation`
